# ClassPilot UI 整体分析与样式优化方案

日期：2026-09-05  
状态：方案待确认，尚未实施样式修改。  
依据：当前工作区、项目 AGENTS.md、PRD §3.4、§5、附录 D。此处假设为保留现有功能与浅色视觉方向的全站优化，不重新设计业务流程。

## 1. 设计结论

保留「浅蓝氛围底、白色卡片、蓝色品牌、业务域色、软几何图表」方向，重点提高一致性、阅读效率和操作辨识度。

- 首页以课表和待办为主，不新增英雄横幅。
- 工作列表以内容密度为主：标题、筛选、结果、分页形成稳定顺序。
- 详情页以信息分组为主：身份、业务内容、操作状态有清楚层级。
- 录入和评语编辑保留工作台布局，优先保证键盘操作和长时间阅读。
- 渐变、阴影只使用已确认用途；普通信息卡通过文字、留白和分隔组织内容。
- 当前不需要新增 UI 库、字体包、图标包或运行时依赖。

本轮是源码级设计审查：已核对全站页面模板、公共布局、样式基础和图表封装；尚未进行真实浏览器截图与交互验收。以下明确区分源码事实和需在浏览器验证的风险，不把推断当成已复现问题。

## 2. 工程与页面结构

- `backend/`：NestJS 业务模块、认证、数据库、审计、加密与 AI 服务。
- `frontend/src/api/`、`stores/`、`router/`：请求、共享状态与页面入口。
- `frontend/src/layouts/AppLayout.vue`：侧栏、顶栏、内容滚动与全局速记。
- `frontend/src/styles/tokens.css`：设计令牌与 Element Plus 主题绑定。
- `frontend/src/styles/global.css`：基础样式、公共辅助类、控件覆盖、导航和动画。
- `frontend/src/components/`：导航、速记、课表、成绩简报及图表组件。
- `frontend/src/constants/chart.ts`：正式业务图表视觉源；`chartStyles.ts` 服务风格对照，不能变成第二套业务主题。
- `frontend/src/views/`：20 个业务页面、2 个对照预览页和1个占位页。
- `deploy/`：部署脚本与 Nginx/pm2 配置。本轮不修改。

现有模块划分适合当前产品规模。前端维护压力主要在单页体积和样式重复：学生详情约 2345 行、成绩录入约 1378 行、分析中心约 941 行、评语工作台约 900 行。行数只表示阅读成本，不作为强制拆分依据；此次只在存在明确复用或独立视觉职责时抽取局部组件，避免顺带重构数据流。

## 3. 现状与问题优先级

### P0：先统一规范口径并保护交互

1. **PRD 存在互相冲突的视觉规格。** 详见第 4 节，实施前需确认。
2. **工作区已有样式优化。** `global.css`、`StudentListView.vue`、`IncidentListView.vue`、`ScoreListView.vue` 已修改，`utils/domainColor.ts` 为未跟踪文件。应以当前工作区为基线逐段整合，不覆盖为 Git 版本。
3. **输入控件存在全局固定高度覆盖。** `global.css` 对 `.el-select__wrapper`、`.el-select__selection`、日期控件等内部结构设置高度。多选标签、长文本、不同 size 的实际表现需重点验证；不能用新增全局 `!important` 持续修补。
4. **内容横向溢出需验证。** 页面整体最小宽度为 1200，但内容区 `overflow-x: hidden`，展开侧栏宽 244；长筛选条、多列工作台可能被裁切。应在桌面宽度范围内明确各块最小宽度、收缩与局部滚动责任。

### P1：全站视觉一致性

1. **令牌覆盖不完整。** `AppSidebar.vue`、`AppTopbar.vue`、`WeeklyScheduleCard.vue`、`DashboardView.vue` 等仍有硬编码颜色、圆角或阴影。课表自建 `--tt-*` 色板；全局域色标签仍使用直接 rgba。将已有语义归入 `tokens.css`，不把所有任意数值机械新增为令牌。
2. **白名单之外的装饰。** 课表单元格、关注预警卡、散点组件容器存在局部渐变或自定义阴影。保留 PRD 明确要求的今日实心高亮与预警边框，装饰改用被批准的令牌与用途。
3. **尺寸与密度漂移。** 默认标签目前 26px/14px，PRD 为约 22px/12–13px；成绩录入行目前 56px，PRD 成绩行 48px。不能简单统一行高而压掉上一场成绩提示，应先验证双行内容实际高度。
4. **主次层级不稳定。** 顶栏速记与页面 primary 同时存在；标题、英雄区、区块标题采用不同强调方式。建议明确「页面内容一个主操作、全局速记独立入口」口径。
5. **状态展示不统一。** 有的页面提供完整空态，有的只有 `el-empty` 描述；生成前、无搜索结果、真正无数据、加载失败需要不同文案和已有操作入口。
6. **图表样式仍有绕行。** `ScoreBriefSection.vue` 存在直接白色描边，需引用 `chart.ts`；正式页面逐项检查轴、图例、tooltip、正负语义色与数字格式。

### P2：可维护性与细节

- `AppLayout.vue` 的标题映射未覆盖沟通话术、工作总结、回收站及事件详情等路径，顶栏可能回退为 ClassPilot。补齐展示映射，不改路由地址。
- `VChart.vue` 已有 ResizeObserver 与卸载清理，但初始化发生在有效尺寸判断之前；隐藏 Tab 场景应延迟初始化，并保持最新 option。
- `prefers-reduced-motion` 目前只关闭待办波动，页面进入、路由切换与 hover 位移也应覆盖。
- 键盘焦点、仅图标按钮名称、超长学生姓名/考试名/文件名应纳入验收，不能仅检查 hover。
- 前端清单为 Vite 6、Pinia 3，与规则中的 8、4 不同。这是独立的工程版本问题，不在此次样式工作中自动升级。

## 4. 需要确认的规范口径

PRD 要求发现矛盾先确认。以下均是建议，尚未作为实现决定：

1. **弹窗尺寸。** D.1 与现有 token 为圆角 16，D.4 为 12；建议采用现有 16。480/720 作为常规宽度，现有复杂导入预览保留更宽尺寸并检查视口边界。
2. **字号。** D.2 声称六档但只列 13/14/15/18/22；D.4 又有弹窗标题 16 和标签 12–13，现有按钮 token 为 16。建议正文采用五档，按钮与弹窗标题保留专用 16，紧凑标签优先 13；图表遵循 D.5 的 11–12，不强行放大。
3. **侧栏。** D.3 示意展开 220、折叠 64，文字为约 72，现有实现 244/72。建议采用 220/72，给业务内容更多宽度，菜单长标签单独验证。
4. **渐变。** D.3/D.9 要求导航选中浅蓝渐变，D.1/D.8 白名单未包含该用途。建议把导航选中渐变列为唯一明确追加例外，集中令牌化；其他卡片不追加用途。
5. **标签文字。** D.1 要求浅底深字，但同时规定用较浅的域色原值作为文字，金色/绿色小字存在阅读风险。建议保留域色图形、边条和浅底，标签文字使用同域深色 token；需批准这一视觉口径调整。
6. **主操作数量。** 建议“每页最多一个 primary”按页面内容区计算，保留顶栏速记这一全局主入口；弹层按其自身操作区计算。

用户确认后，在 PRD 的相应段落同步最终口径，避免实现与文档继续分叉；不会在确认前修改 PRD。

## 5. 页面优化清单

### 公共外壳与设计基础

文件：`styles/tokens.css`、`styles/global.css`、`layouts/AppLayout.vue`、`components/AppSidebar.vue`、`components/AppTopbar.vue`。

- 统一颜色、文本、间距、圆角、阴影及已批准渐变的语义定义。
- 保留顶栏 56px、内容间距 24px、最小视口 1200px；宽屏使用内容空间，不加内容最大宽度。
- 导航清晰显示选中、悬停、折叠和焦点状态，系统设置保持顶栏入口。
- 公共类负责标题、筛选、卡片、行内操作和数字；页面样式只负责自己的布局。
- 优先使用 Element 变量和公开类配置，仅必要时在业务容器内限定内部选择器。
- 设置 `min-width: 0`、合理文本换行和局部溢出策略，避免用整页隐藏掩盖问题。

### 首页与课表

文件：`views/dashboard/DashboardView.vue`、`components/WeeklyScheduleCard.vue`、`components/ScoreBriefSection.vue`。

- 维持课表左、待办/关注右，成绩简报下置；无成绩时整个简报隐藏。
- 课表区分表头、时段、课程与今日列；统一色板，减少每格装饰；保持英语/早读班级展示规则。
- 待办标题、数量、全部入口对齐；关注卡保留脱敏方式和沟通超期提示。
- 长姓名、长待办摘要有可读取的截断/换行方式；不扩大敏感内容展示范围。

### 学生档案

文件：`views/students/StudentListView.vue`、`StudentDetailView.vue`、`utils/domainColor.ts`。

- 延续已有姓名头像、域色标签和班干部列设计；身份列、状态列、操作列对齐。
- 筛选与分页保持清楚边界；空态提供现有新增/导入入口。
- 详情维持 64px 头像、身份条和 Tab 白卡结构，正文不低于 15px。
- 时间线类别边条、节点与标签语义一致；敏感区仅改善视觉分组，保留 PIN 和隐藏状态。

### 成绩管理

文件：`views/scores/ScoreListView.vue`、`ExamDetailView.vue`、`ScoreEntryView.vue`。

- 考试列表统一时间、考试状态、主入口及行内次操作。
- 全科表数字等宽；成绩/排名列统一密度；排序标识、固定列和横向滚动保持可见。
- 录入保持全屏和键盘导航；工具区突出考试、科目、进度、保存状态。
- 已录、未录、缺考、免考、非法输入、当前焦点分别有稳定视觉；焦点框不造成单元格跳动。
- 不改写录入聚合、导入覆盖策略或排名算法；对行高调整先做双行内容验证。

### 事件记录与速记

文件：`views/incidents/IncidentListView.vue`、`IncidentDetailView.vue`、`components/QuickNoteDialog.vue`。

- 延续现有两列事件卡和宽屏三列方向；左条始终表示事件类别，跟进状态用独立文字/标签。
- 学生 chips、严重度、时间与后续动作分组，控制标题和摘要长度。
- 详情按事件信息、学生、附件、跟进结果组织，现有确认/删除流程保持完整。
- 速记字段紧凑且标签明确；Alt+Q、焦点、保存及关闭行为保留。

### AI 与知识库

文件：`views/ai/` 下 6 个业务页面，`views/knowledge/KnowledgeListView.vue`、`KnowledgeAskView.vue`。

- 评语工作台保持学生列表、编辑与上下文的职责分区；选中学生和草稿/完成状态清晰。
- 学情问答与知识库问答统一输入区、结果排版、引用和会话侧栏样式，保留不同数据来源与入口。
- 话术和总结保持表单→生成结果结构；空白生成区用已有引导文案而非堆叠占位卡。
- 模板与生成历史统一列表/编辑器/抽屉密度；长模板、长回答、引用路径可换行。
- 生成中、失败和已有结果状态清楚；不得在样式调整中隐藏错误或添加新 AI 调用。

### 分析、系统与登录

文件：`views/analysis/AnalysisView.vue`、`components/SubjectScoreScatter.vue`、`components/VChart.vue`、`constants/chart.ts`、`views/settings/SettingsView.vue`、`views/recycle/RecycleBinView.vue`、`views/auth/LoginView.vue`。

- 分析页按现有图表主题组织标题、筛选和图例，保持比较顺序；宽屏栅格适配仅限桌面。
- 散点图、简报、详情及分析复用正式主题，不另建色板；隐藏 Tab 再打开能够正常 resize。
- 设置分区保留现有功能，备份恢复等危险操作保持二次确认与清楚说明。
- 回收站恢复入口与状态清楚，不增加物理删除入口。
- 登录页沿用品牌与表单体系，聚焦登录任务，不新增宣传信息或摄影背景。

### 对照页面

文件：`views/preview/UiPreviewView.vue`、`ChartStylesPreviewView.vue`、`constants/chartStyles.ts`；占位页仅检查全局样式影响。

- 保持对照用途，规范口径更新后同步必要示例；不改变预览路由是否公开。
- 历史图表风格对照不接入业务页面。

## 6. 实施顺序与风险

1. **确认本方案及第 4 节口径。** 同步最终 PRD 口径；不改变功能范围。
2. **公共基础。** 修改 token、公共样式、外壳与导航。风险最高的是 Element 内部覆盖和所有页面同时受影响；先验证输入、下拉、多选、表格、弹窗再扩展页面。
3. **高频页面。** 首页、花名册、事件列表、考试列表先落地，再做学生详情与成绩录入。已有用户改动逐段合并；不批量覆盖文件。
4. **其余页面与图表。** 完成 AI、知识库、分析、设置、登录和回收站的一致性调整。复用仅限展示层，生成及保存状态继续使用原数据源。
5. **统一验收。** 对照页面、实际业务页面与关键状态一起检查，修复本轮引入的问题。

不新增运行时依赖，不修改 API、数据库、认证、后端、部署、CI，不自动提交。若实施中确实需要越过上述范围，单独列出目标、文件与风险再确认。

## 7. 验收标准

### 静态检查

- 组件 CSS 不再新增硬编码颜色、阴影、圆角或渐变；现有违规按本轮覆盖范围清理，令牌定义及正式图表常量为明确例外。
- 所有 dialog 保留 `append-to-body`、`align-center`，drawer 保留 `append-to-body`。
- 正式业务图表使用 VChart 和 chart.ts；仅使用已注册图表组件。
- 数字列使用 `tabular-nums`；错误、缺考、免考不只靠颜色区分。
- 任何新增观察器、事件、帧回调都具有清理策略。

### 桌面浏览器检查

- 1200×800、1440×900、1920×1080；展开/折叠导航。此为桌面布局验证，不扩展移动端需求。
- 长姓名、长考试名、多标签、长文档名、超长回答；无数据、筛选无结果、加载和错误状态。
- 表格横向滚动与固定列；窄桌面下筛选控件可操作；纵向只在明确区域滚动。
- 输入框、日期范围、多选、弹窗、抽屉、下拉和 tooltip 不被裁切。
- 页面主操作、危险操作和键盘焦点可辨识；减弱动画偏好生效。
- 图表切换 Tab、折叠侧栏后尺寸正确；标题、图例、轴标签不互相覆盖。

### 功能回归边界

- 登录、导航、全局速记；学生筛选、详情 Tab、敏感字段锁定状态。
- 成绩键盘移动、录入状态、保存反馈、导入预览与排序；只在隔离测试数据上执行写入验证。
- AI 表单、结果、引用和失败提示；不为视觉验收消耗真实 API 配额。
- 备份与恢复仅验证布局和确认流程，不执行真实恢复或迁移。
- 运行现有 `npm run build`（frontend：vue-tsc + Vite）。当前仅有 build/dev/preview 脚本，不声称已有测试覆盖。
